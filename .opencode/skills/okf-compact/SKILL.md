# OKF temporal compaction

`okf-consolidate` is **spatial**: one claim landed in three concepts, move it to its
canonical concept-type home. This skill is **temporal**: one concept's own history has
piled up as an append log and must collapse into tiers. The two compose — compact first,
then consolidate the deduplicated result. Read `rules.md` §7 and §7.1 before planning.

## The tier model

```
# Current Situation      present state only; rewritten every run
# Recent Developments    TIER 1  per-day paragraphs under ### <Month D, YYYY> headings
# Chronology             TIER 2  sealed, named periods
# Analysis               TIER 3  durable, thematic, dateless
# Citations              always terminal; generated by script, never hand-edited
```

Resolution decays with age. Daily incorporation only ever appends to Tier 1. **Every
destructive operation in this bundle happens here**, in a deliberate manually-triggered
run — never in the automated daily path.

A written Tier-2 period is **sealed**: routine runs must not re-cut, rename, reword or
merge it. Sealed text is re-summarized by exactly one mechanism, the rollup step below.
This is what keeps each run bounded and stops repeated lossy re-summarization from
eroding the record over time.

## Build the worklist

```bash
python3 .opencode/okf/okf_core.py compact-scan
```

Emits, per concept: whether it is still unmigrated (dailies sitting in
`# Current Situation`), the Tier-1 days, which have aged past the window and are
therefore eligible for demotion, the sealed period headings, and whether rollup is due.
It also emits the current `config` block — quote those numbers to subagents rather than
hardcoding them here.

Do not widen scope beyond what `compact-scan` reports. Compaction never touches
`sources/`, never creates concepts, and never adds evidence.

## Delegate one subagent per concept

Spawn a **fresh subagent per concept** so context does not accumulate across the run and
quality does not decay toward the end. The coordinator does no concept rewriting itself.

Each brief must state, and must be limited to:

- the one file, and the eligible days from `compact-scan`;
- the sealed period headings, named explicitly, as off limits;
- period boundaries within `period_min_days`–`period_max_days`, contiguous,
  non-overlapping, covering every eligible day exactly once, named for the operational
  character of the period (`### January 7–18, 2025 — The Refractory Plant Fight`);
- rewrite `# Current Situation` to the present state as of the newest Tier-1 day;
- leave Tier-1 days inside the window exactly as they are.

**Compaction guidance is by principle, not checklist.** Preserve what a reader needs in
order to understand how the sector evolved — confirmed terrain change, the shape and
method of the fight, what proved durable. Shed day-level repetition: uncorroborated
claims that were never confirmed, restatements of the same force composition, routine
enumerations of unchanged attack locations. A period paragraph is a synthesis, not a
concatenation.

**One invariant is mechanical, not judgment:** every source that fed a period stays
cited on that period paragraph even where its specific claim was compressed away.
Provenance survives compaction even when detail does not.

Subagents cite by **source key** — `[isw:2025-01-18]` — and never touch numbers or the
`# Citations` block. `log.md` and indexes stay exclusively coordinator-owned.

## Verify each concept

Because the guidance above is principle-based, every rewritten concept gets a **fresh
verifier subagent** that sees the original daily paragraphs and the new period text and
answers one question: *name any ISW-confirmed fact present before and absent now.*

Findings go back to the writing subagent for exactly **one** revision pass. Anything that
survives that pass marks the concept blocked; restore it unmodified and report it. Do not
argue with the verifier across multiple rounds.

## Roll up when periods accumulate

When `compact-scan` reports `rollup_due`, run a **separate bounded invocation** that
merges the oldest adjacent sealed periods into a Tier-3 `# Analysis` phase narrative,
organized thematically per `rules.md` §8. This is the only path by which sealed text is
ever rewritten, and it is the layer where the bundle's long-run bigger picture lives.

Rollup obeys the same citation invariant: the phase narrative carries the union of the
merged periods' sources.

## Close the run

Coordinator-owned, in order:

```bash
python3 .opencode/okf/citations.py normalize <changed-paths>
python3 .opencode/skills/okf-incorporate/scripts/validate.py
python3 .opencode/okf/okf_core.py analyze --base <baseline-commit>
```

`citations.py normalize` assigns numbers in order of first appearance and regenerates
`# Citations`; it refuses to write a file whose markers it cannot resolve. Treat any
refusal as a blocked concept, not something to fix by hand — hand-editing numbered
citation lists is what corrupted 20 files in commit `0d43e88`.

Gate, all of which must hold:

- zero validator errors;
- no new warnings against the baseline captured before the run — never call a warning
  "pre-existing" without showing it in that baseline;
- every concept verifier-passed;
- re-running `compact-scan` reports no newly eligible work for the concepts just
  processed (idempotence).

Then refresh `timestamp` on changed concepts, add a `log.md` entry naming the concepts
compacted and the periods created, and commit as `Compaction: YYYY-MM-DD`.

**Never push.** If any gate fails, leave the failing concepts unmodified, report them,
and stop.
